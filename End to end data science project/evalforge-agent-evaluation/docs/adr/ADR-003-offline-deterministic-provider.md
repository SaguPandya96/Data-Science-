# ADR-003: Require an offline deterministic provider

- **Status:** Accepted
- **Date:** 2026-08-04
- **Deciders:** Project author

## Context

An evaluation harness that requires paid API credentials to run has three problems:

1. **It cannot gate CI.** Secrets in pull-request workflows are a supply-chain risk, and
   a test suite that costs money per run will be disabled the first time someone
   notices the bill.
2. **It cannot be reviewed.** Anyone cloning the repository — a reviewer, an
   interviewer, a future maintainer — hits a wall before seeing anything work.
3. **It cannot support a regression gate.** Comparing baseline against candidate
   requires that the *only* thing that changed is the thing under test. Sampling noise
   from a real model makes a 3-point regression tolerance meaningless.

## Decision

`MockModelProvider` is a **mandatory, first-class component**, not a test double. It
powers the entire test suite, the whole of CI, and `evalforge demo`.

It simulates a competent agent from scenario metadata, then applies degradation drawn
from a named `BehaviorProfileConfig`. Eleven behaviours are modelled: correct execution,
context loss after N turns, instruction forgetting, goal drift, wrong tool selection,
wrong tool arguments, excessive tool calls, failed recovery, unsupported claims,
prompt-injection compliance and cascading errors.

Every decision is drawn from an RNG seeded on `(run_seed, scenario_id, turn_index,
aspect)`, so the same inputs always produce the same session — on any machine, in any
order, in parallel.

External providers (`anthropic`, `openai`) are optional. Missing credentials raise
`ProviderUnavailableError` naming the mock fallback, rather than failing obscurely.

## Consequences

**Positive**

- CI runs the full pipeline on every push with no secrets and no cost.
- The regression gate is trustworthy: baseline-versus-candidate deltas contain zero
  sampling noise, so a 3-point tolerance means exactly what it says.
- Golden-fixture regression tests are possible at all — an evaluator change that shifts a
  known-failing fixture's score is caught immediately.
- The demonstration is reproducible by anyone, forever, with no dependency on a model
  that may be deprecated.

**Negative — and this is the important one**

- **Mock results say nothing about any real model's competence.** The mock produces the
  behaviour it was configured to produce. Every reported number in this repository
  measures *the evaluation system*, not an LLM.
- Mitigations: every generated report carries the banner "Deterministic demonstration
  results using simulated model behavior"; `docs/LIMITATIONS.md` states it plainly; no
  commercial model is named in any result.
- There is a real risk of the mock and reality diverging — the mock cannot exhibit a
  failure mode nobody thought to implement. Partially mitigated by the `perfect` and
  `broken` profiles, which test evaluators for false positives and false negatives
  respectively, but not eliminated.

## Alternatives considered

**Record/replay against a real model.** Genuinely attractive: real behaviour, replayable
in CI. Rejected for this project because the cassettes are only valid for one model
version, cannot be regenerated by a reviewer without credentials, and cannot produce the
*controlled* degradation the regression demonstration requires — you cannot ask a real
model to lose context after exactly turn 10.

**A tiny local open-weights model.** Real inference, no API cost. Rejected: multi-GB
weights, slow CI, still non-deterministic across hardware, and its failure modes would
be its own rather than a controlled set.

**Skip tests when credentials are absent.** Rejected outright — a test suite that
silently degrades to nothing is worse than no test suite, because it reports green.
