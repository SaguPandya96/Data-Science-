# Repository Operating Rules

- Use only real, publicly available data with documented provenance.
- Never create synthetic business records or fabricate findings, metrics, citations, test outcomes, or impact.
- Preserve every file in `data/raw/` byte-for-byte after acquisition.
- Use chronological validation for every performance claim.
- Prevent target leakage and verify historical features use prior observations only.
- Run the relevant automated tests after meaningful code changes.
- Keep README metrics synchronized with generated machine-readable metrics.
- Use repository-relative paths in code, configuration, commands, and documentation.
- Preserve unsuccessful experiments and negative findings.
- Never include secrets, credentials, private information, or machine-specific paths.
- Present the work solely as Sagar Pandya's personal portfolio project; do not discuss its creation tools or employment contexts.
- Do not claim completion until the data, training, notebook, scoring, dashboard, and tests have been executed and verified.
